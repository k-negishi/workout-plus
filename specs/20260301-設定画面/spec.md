# Feature Specification: 設定画面

**Feature Branch**: `20260301-設定画面`
**Created**: 2026-03-01
**Status**: Draft
**GitHub Issue**: [#169](https://github.com/k-negishi/workout-plus/issues/169)

## 概要

ワークアウトアプリの設定画面を実装する。ユーザーが週の目標回数を設定してホーム画面での進捗確認、および招待コードを入力して限定機能を解禁できる。その他の設定項目は WF の UI シェルを表示するが、機能実装は後続スプリントに委ねる。

## 前提条件

- 設定画面はタブバーの5つ目のタブ（歯車アイコン）としてアクセスする
- ホーム画面ヘッダーの設定アイコンプレースホルダーは削除または非表示にする
- 週の目標のデフォルト値は 3 回とする
- 招待コードの有効値は `.env` 環境変数（`EXPO_PUBLIC_INVITE_CODE` 等）でビルド時に注入し、アプリバンドル内で検証する（サーバー通信なし・オフライン動作）
- 招待コードで解禁される「限定機能」の具体的内容は本仕様スコープ外（フラグ永続化のみ実装）
- MVP スコープは「ワークアウト（週の目標）」「限定機能（招待コード）」「その他（利用規約・プライバシーポリシー準備中・バージョン）」の 3 セクション。アプリ設定・データ管理セクションは後続 Issue
- 設定値は既存 SQLite に `user_settings` テーブル（1行・型付きカラム）を追加して永続化する。migration で管理:
  ```sql
  CREATE TABLE user_settings (
    id                   INTEGER PRIMARY KEY CHECK (id = 1),
    weekly_goal_count    INTEGER NOT NULL DEFAULT 3,
    invite_code_unlocked INTEGER NOT NULL DEFAULT 0
  );
  ```
  将来設定追加時は `ALTER TABLE ADD COLUMN` で migration に追記

## 確認事項

### セッション 2026-03-01

- Q: 設定画面へのアクセス導線は？ → A: タブバーに歯車アイコンを追加（5つ目のタブ）。ホームヘッダーの設定アイコンは削除
- Q: 招待コードの検証方法は？ → A: `.env` で git から秘匿してビルド時に環境変数として注入し、アプリ内で検証
- Q: 週の目標の変更操作 UI は？ → A: 設定列の右側に `[−] 回数 [+]` ボタンをインラインで並べる
- Q: MVP のスコープは？ → A: アプリ設定・データ管理セクションは除外。「ワークアウト（週の目標）」「限定機能（招待コード）」「その他（利用規約・プライバシーポリシー準備中・バージョン）」の 3 セクションに絞る
- Q: 利用規約・プライバシーポリシーは？ → A: その他セクションに表示するが「準備中」バッジで非活性（タップ不可）
- Q: 設定値の永続化方式は？ → A: SQLite `user_settings` テーブル（1行・型付きカラム）。`id=1` 固定の単一行、将来追加は `ALTER TABLE ADD COLUMN`
- Q: 解禁済み状態で招待コードを再入力しようとした場合の挙動は？ → A: 解禁済み時はフォームを非表示にして「解禁済み」バッジのみ表示する。再入力シナリオは存在しない（EC-005 を削除）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 週の目標を設定してホームで進捗確認 (Priority: P1)

ユーザーが設定画面から「週の目標」（週に何回ワークアウトするか）を変更し、ホーム画面でその週の達成進捗が反映されることを確認できる。

**Why this priority**: ホームの動機付け表示と直結しており、アプリの継続使用を後押しするコア機能。

**Independent Test**: 設定画面で目標回数を `[−]`/`[+]` で変更 → ホーム画面に戻って「今週 X / Y 回」の Y が更新されていれば動作確認完了。

**Acceptance Scenarios**:

1. **Given** 設定画面を初めて開いた状態で、**When** 週の目標項目を確認すると、**Then** `[−] 3回 [+]` が表示され、デフォルト値（3 回）が選択済みで表示される
2. **Given** `[+]` ボタンを 2 回タップして目標を 5 回にした状態で、**When** ホーム画面に戻ると、**Then** 今週の進捗が「X / 5 回」形式で表示される
3. **Given** アプリを再起動した状態で、**When** 設定画面を開くと、**Then** 前回設定した目標回数が保持されている
4. **Given** 今週すでに 3 回ワークアウトした状態で、**When** 目標を 3 回に設定すると、**Then** ホームの進捗が「3 / 3 回（達成）」と表示される

---

### User Story 2 - 招待コードを入力して限定機能を解禁 (Priority: P2)

ユーザーが招待コードを入力し、正しいコードが認証されると限定機能フラグが永続的にオン（解禁済み状態）になる。

**Why this priority**: 初期ユーザー獲得やクローズドベータの運用に使用するマーケティング施策と連動している。

**Independent Test**: 設定画面で正しい招待コードを入力 → 「解禁されました」メッセージが表示され、アプリ再起動後も解禁状態が維持されることを確認。

**Acceptance Scenarios**:

1. **Given** 招待コード未入力の状態で、**When** 設定画面の「招待コード」項目をタップすると、**Then** コード入力フォームが表示される
2. **Given** コード入力フォームに有効なコードを入力した状態で、**When** 「適用」ボタンをタップすると、**Then** 「限定機能が解禁されました」のメッセージが表示され、解禁フラグが保存される
3. **Given** コード入力フォームに無効なコードを入力した状態で、**When** 「適用」ボタンをタップすると、**Then** 「コードが正しくありません」のエラーメッセージが表示され、何も解禁されない
4. **Given** すでに限定機能が解禁済みの状態で、**When** 設定画面の招待コード項目を確認すると、**Then** 「解禁済み」バッジが表示される

---

### User Story 3 - 設定画面を閲覧する (Priority: P3)

ユーザーがタブバーの歯車アイコンをタップして設定画面を開き、WF に準拠したレイアウトで各設定項目を確認できる。

**Why this priority**: 設定画面自体の導線とレイアウト確立が他のストーリーの基盤となる。

**Independent Test**: タブバーの設定タブをタップして設定画面が開き、所定のセクションとアイテムが表示されれば動作確認完了。

**Acceptance Scenarios**:

1. **Given** アプリ起動済みの状態で、**When** タブバー右端の歯車アイコンをタップすると、**Then** 設定画面がタブ遷移で表示される（戻るボタンなし、「設定」タイトルのみ）
2. **Given** 設定画面表示中に、**When** 画面を確認すると、**Then** 「ワークアウト」セクション（週の目標）・招待コード行（セクションタイトルなし）・「データ管理」セクション（データインポート／エクスポート）・「その他」セクションが順に表示される（「アプリ設定」セクションは今回スコープ外）
3. **Given** 設定画面表示中に、**When** データインポート・データエクスポートの行を確認すると、**Then** 「準備中」ラベルが表示されてタップ操作が無効になっている

---

### Edge Cases

- `[−]` ボタンを 1 回のときに押した場合、1 回より下には減らず変化なし
- `[+]` ボタンを 7 回のときに押した場合、7 回より上には増えず変化なし
- 招待コードにスペースや特殊文字が含まれる場合、前後のスペースをトリムしてから検証する
- 招待コードが空欄の状態で「適用」ボタンをタップした場合、ボタンを非活性化して何も起こらない
- ホーム画面の今週の件数取得時に週の境界（月曜 00:00 起点）を正しく計算する

## Requirements *(mandatory)*

### Functional Requirements

**設定画面レイアウト・導線**

- **FR-001**: システムは WF（workout_plus_wireframes_v5_md3.html 6d）に準拠した設定画面を表示しなければならない
- **FR-002**: 設定画面は「ワークアウト」「（タイトルなし: 招待コード行）」「データ管理」「その他」の 4 セクションで構成しなければならない（「アプリ設定」セクションは後続 Issue で追加）
- **FR-003**: データインポートおよびデータエクスポートは UI に表示するが、「準備中」ラベルを付与してタップ操作を無効にしなければならない
- **FR-014**: タブバーに5つ目のタブ（歯車アイコン・ラベル「設定」）を追加し、タップすると設定画面へ遷移しなければならない
- **FR-015**: 設定画面のヘッダーには「設定」タイトルを表示する（タブ画面のため戻るボタンは不要）
- **FR-020**: ホーム画面ヘッダーの設定アイコンプレースホルダーは削除または非表示にしなければならない

**週の目標設定**

- **FR-004**: ユーザーは週の目標ワークアウト回数を 1〜7 回の整数で設定できなければならない
- **FR-005**: 目標回数の初期値は 3 回でなければならない
- **FR-006**: 目標回数の変更はアプリ再起動後も永続化されなければならない
- **FR-007**: ホーム画面は今週の実施済み回数と目標回数を反映した進捗を表示しなければならない
- **FR-008**: 今週の集計は毎週月曜日 00:00 起点とし、日曜日 23:59 に週がリセットされなければならない
- **FR-016**: 週の目標の変更は設定列の右側に配置した `[−] 回数 [+]` ボタンをタップして行う（画面遷移なし）
- **FR-017**: `[−]` ボタンは現在値が 1 のとき、`[+]` ボタンは現在値が 7 のとき、それぞれ非活性にしなければならない

**招待コード**

- **FR-009**: ユーザーは招待コードを入力して「適用」ボタンでコードを送信できなければならない
- **FR-010**: 有効な招待コードを入力すると、限定機能フラグが永続的にオンになりアプリ再起動後も維持されなければならない
- **FR-011**: 無効な招待コードを入力した場合、エラーメッセージを表示し何も変更してはならない
- **FR-012**: 解禁済み状態では設定画面の招待コード項目に「解禁済み」バッジを表示しなければならない
- **FR-013**: 招待コードの検証は入力値の前後スペースをトリムしてから行わなければならない
- **FR-018**: 有効な招待コードの値はビルド時に環境変数（`EXPO_PUBLIC_*` 形式）として注入し、アプリ内でオフライン検証しなければならない（サーバー通信なし）
- **FR-019**: 招待コードが空欄の場合、「適用」ボタンを非活性化しなければならない

### Key Entities

- **user_settings テーブル**: `id=1` 固定の単一行。`weekly_goal_count INTEGER DEFAULT 3`、`invite_code_unlocked INTEGER DEFAULT 0`。将来設定追加は `ALTER TABLE ADD COLUMN`
- **WeeklyGoal**: 週の目標回数（1〜7）と今週達成済み回数（完了ワークアウト数のカウント、月曜起点）
- **InviteCode**: ビルド時に `EXPO_PUBLIC_*` 環境変数で注入された有効コード。`invite_code_unlocked` フラグで解禁状態を永続化

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーが週の目標を `[−]`/`[+]` で変更してホーム画面に戻るまでの操作が 3 タップ以内で完結する
- **SC-002**: 招待コード入力から解禁確認メッセージ表示まで 5 秒以内に完了する（オフライン検証のため）
- **SC-003**: 設定値（週の目標・解禁フラグ）がアプリ再起動後も 100% 保持される
- **SC-004**: 設定画面の全セクションが WF のレイアウトと視覚的に一致していると確認できる
- **SC-005**: データインポート・エクスポート行が「準備中」表示でタップ不可になっており、誤タップによるクラッシュが 0 件である
